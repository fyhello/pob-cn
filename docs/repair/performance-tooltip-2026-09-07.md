## 已确认的原始瓶颈

原实现 `includeTooltip == false and nil or officialTooltipProjection(...)` 不会跳过浮窗：Lua 中 `true and nil or f()` 仍执行 `f()`。因此天赋、装备、技能每次批量投影仍构造全部物品浮窗，并触发大量官方物品比较计算。这是通过真实调用计数和修复前后对照确认的缺陷，不是根据耗时猜测。

以下数据来自清理前的专项对照，不是本轮重新测量。相同 BD 修复前后各执行天赋、装备、技能 20 次，共 120 次、60 对匹配状态。中位数单位毫秒，偶数样本取中间两项平均；不同阶段中位数不可直接相加。

| --- | ---: | ---: | ---: |

| 请求至 JSON | 2602.2 / 307.15 | 2176.95 / 213.1 | 2343.45 / 236.15 |
| JSON 至 DOM | 18.5 / 15.95 | 17.7 / 18.9 | 27.65 / 20.15 |

天赋、技能每次 26 次浮窗构造、101 次物品比较降至 0、0。装备每次 26～27 次浮窗、102 次比较降至卸下 0、0，装回 1、1；装回的单物品构造按原契约保留。官方主 `BuildOutput` 每次仍执行 1 次。

历史正确性对照：60 对官方输出一致；递归排除按设计省略的 `tooltip` 后，60 对完整投影一致。使用 XML 解析器归一属性及官方无序容器后，60 对 XML 内容一致，但不是字节一致。无序容器为 `PathOfBuilding2`、`ConfigSet`、`ItemSet`、`Sockets`，`Calcs` 只排序 Input，其余有序内容保留。天赋、装备、技能各两种保存状态，分别在新核心中导入后，6 种输出一致。

## 限制与既有问题

GitNexus 的 Lua 调用图和新增符号覆盖不全，不能将文件级 LOW 当作完整风险保证；物品提交入口影响装备和珠宝路径，已做针对性回归及浏览器核验。agy 多次只读核验超时，未取得评审结论，不能列为通过。

同一官方核心连续 `loadXML` 导入不同 XML 时，第二次起可能保留第一次状态。备份版与修复版均复现，单独新核心导入则正确。本次未扩改该既有导入问题，也未将同进程连续重导入列为验证通过。

本轮样本确认保留提速效果并修正技能明细遗漏，不承诺所有 BD、设备或高频操作具有相同延迟上界。
